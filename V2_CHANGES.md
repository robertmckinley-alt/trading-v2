# v2: what changed and how to roll it out beside v1

Cut date: 2026-11-10. Source: v1 `robertmckinley-alt/trading` at commit `97492b0`.

## Why

Across v1's 15 paper accounts: 217 forward trades, net **+$1,008** on $750k of paper capital. Win rate 28.6% against a 28.6% break-even rate for the observed 2.48R winners / -0.99R losers. Roughly $5,200 of the ~$6,200 gross went to commission and slippage, most of it generated by accounts whose own backtests were negative. v2 keeps the three accounts that were net positive forward and removes everything else, so that the next round of work (exit management, sizing) is done on strategies with a chance of an edge.

## Removed

**Strategies and paper accounts** (12): RUNNER, DMC Failed-Level Reversal, DMC Gain + Retest, NQ DMC Market Open, Gold Open EMA12, 1H Sweep + iFVG + 1M BOS, NQ Opening Range Breakout, EMA 20/60 Momentum, Volume POC Reversion (+ "Exclude balanced" challenger), NQ 15M Opening Range Retest, NQ 15M ORB Close Confirmation (+ 9 ORB forward variants), NQ HTF Session Sweep.

**Research-only definitions** (17): all ORB research/filter/extension variants, price-action patterns (QM retest, S/R flip, compression), Hourly/EMA/POC/15M-retest tests.

**Subsystems**: adaptive-bots (risk multipliers), strategy-learning, challenger accounts, research council, pattern matching, profit-preservation experiment, regime (HMM) experiment, coordination shadow, ORB discovery/learning/forward supervisor, DMC level bots and paper collection, gold feed, NFL pages and libs, crypto/TAP/flow checks in the operations monitor.

**Numbers**: `lib/` 68 → 39 files; `lib/live-trader.cjs` 1,818 → ~720 lines; strategy registry 33 → 4 definitions; tests 192 → 141 (removed tests covered removed code; three generic tests were re-pointed at kept slugs).

## Behavior changes you should know about

1. **Fixed risk per trade.** v1's adaptive sizing (0.5×–1× multipliers from regime/streak/learning, with a $250 floor) is gone. Each strategy risks its configured amount every trade. The daily-loss pause (`maxDailyLossUsd`) and account-floor pause are re-implemented in `lib/risk-guard.cjs`; the shared $2,500 portfolio cap and family caps are unchanged.
2. **VWAP `scanAudit.rulesVersion`** changes from `paper-collection-v2-2026-10-02` to `baseline` because paper-collection was removed. The audit counters restart once on first start; journals and balances are untouched.
3. **`/api/live-status`** no longer has `orbForward`, `coordinationShadow`, `profitExperiment`, `regimeExperiment`. Feed status moved from `orbForward.feed` to a top-level `feed` key.
4. **New-strategy entry.** Adding a strategy means: one entry in `lib/strategy-registry.cjs`, a detector, a window in `lib/watcher-observation.cjs` and `lib/backtest-engine.cjs`, and a line in each of `scripts/start|stop|status-live-watcher.sh`.

## VPS rollout, side by side with v1

v1 lives at `/data/.openclaw/workspace/lucid-nq-paper-trader` inside the `openclaw-anwx-openclaw-1` container and must keep running. v2 goes in a **separate checkout** with its own runtime directory, port, env file and systemd unit names. Nothing below touches v1's files or processes: watcher and feed process matching is scoped to the checkout's own directory.

```sh
docker exec -it openclaw-anwx-openclaw-1 sh -lc '
cd /data/.openclaw/workspace &&
git clone <V2_REPO_URL> trading-v2 &&
cd trading-v2 &&
npm ci && npm test
'
```

Create `/data/.openclaw/workspace/trading-v2/.env.local`:

```
DATABENTO_API_KEY=<same key as v1>
LIVE_STATUS_TOKEN=<new long random value; also set on the v2 Vercel project>
LIVE_STATUS_HOST=127.0.0.1
LIVE_STATUS_PORT=3211
# Share v1's live feed instead of opening a second Databento connection:
LIVE_DATA_CACHE_PATH=/data/.openclaw/workspace/lucid-nq-paper-trader/runtime/databento-live.json
SHARED_FEED=1
```

If you would rather run an independent feed (second Databento live session; check your plan's connection limits), leave out the last two lines.

Start the three watchers and the bridge:

```sh
docker exec -it openclaw-anwx-openclaw-1 sh -lc '
cd /data/.openclaw/workspace/trading-v2 &&
set -a && . ./.env.local && set +a &&
npm run trader:watch:start &&
node scripts/restart-status-server.cjs &&
npm run trader:watch:status
'
```

Reverse proxy: forward a new public path or port to `127.0.0.1:3211` in the same network namespace as the container (same pattern as v1's 3210). Put that public URL in the Vercel project as `LIVE_STATUS_SOURCE_URL`.

Optional host systemd units are in `deploy/systemd/doctortrades-v2-*`. They use `/etc/doctortrades/trading-v2.env` and the `trading-v2` checkout path, so they coexist with v1's units.

Backtest: the status server refreshes the historical report daily using v2's own `runtime/backtest` cache; the first run downloads 2025-to-date NQ history (billed by Databento, same as v1's first run). To reuse v1's cached candles instead, copy `runtime/historical-cache` from the v1 checkout before starting the bridge.

## Vercel

New project, imported from the v2 GitHub repo (Next.js, no special build settings). Environment: `LIVE_STATUS_SOURCE_URL`, `LIVE_STATUS_TOKEN`, optional `DATABASE_URL`. Then update `TRADING_V2_STATUS_URL` for `scripts/operations-monitor.py` if you install the host monitor.
